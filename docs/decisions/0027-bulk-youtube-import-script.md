# 유튜브 링크 일괄 등록 — 로컬 스크립트 + 미리보기 후 저장

날짜: 2026-10-11  
상태: 채택 (실사용 전 — 저장 단계 미실행)

## 배경 (왜 이 결정이 필요한가)

- 기록을 미뤄둔 유튜브 링크가 많다. 링크마다 섹션을 고르고, AI 채우기를 돌리고, AI 도구 영상은 영상을 보고 도구의 GitHub·사이트 링크를 직접 찾아 넣어야 했다.
- 원하는 것: **유튜브 링크만 넘기면** 섹션 분류·내용 채우기·관련 레포 링크·중복 확인까지 자동.

## 결정 (무엇으로 했는지)

1. **로컬 스크립트** `server/scripts/bulk-youtube.ts` (`npm run bulk-youtube -w server -- prepare|save`).
2. **2단계**: `prepare <links.txt>` → `<links>.preview.json` 생성(DB 쓰기 없음) → 사람이 검토(`include`/`section`/`url`/`data` 수정) → `save <preview.json>`.
   저장 즉시 공개되는 구조(초안 없음)라 미리보기를 거친다. 저장된 항목은 `savedSlug` 기록, 재실행 시 건너뜀.
3. **분류**: AI가 칼럼 / 게임 개발 도서관 / AI 개발 도구 중 선택. AI 도구·모델·서비스(에이전트 터미널, AI 비디오 생성 모델 등)를 **주제로 소개하는** 영상은 AI 개발 도구.
4. **AI 개발 도구 관례 유지**: 메인 링크 = 도구의 GitHub 레포(우선) 또는 공식 사이트, 영상은 「소개 영상」 추가 링크. 도구가 여럿이면 도구마다 항목. 링크 찾는 순서: 설명란 github 링크 → AI가 준 레포(이름이 도구와 맞을 때만) → 공식 사이트(접속 확인) → GitHub 이름 검색(★50+, `check` 표시).
5. **칼럼·게임 개발**: 메인 링크 = 영상, 설명란·자막·본문의 GitHub 레포(API로 존재 확인)를 추가 링크.
6. **중복**: 세 섹션의 메인 링크 + 추가 링크의 영상까지 키 비교(유튜브=영상 ID, GitHub=owner/repo, 그 외 host+path). 저장 직전 재확인.
7. **로그인**: `server/.env`의 `BULK_EMAIL`/`BULK_PASSWORD`, 없으면 터미널에서 입력(비밀번호 `*` 마스킹, 저장 안 함).

## 이유 (다른 선택지를 배제한 이유)

| 대안 | 배제 이유 |
|------|-----------|
| 사이트 관리자 페이지 | Vercel IP는 자막이 막혀 영상마다 Gemini 영상 분석(비용·30~60초). 로컬은 자막 직접 수신이라 저렴·빠름 |
| 바로 저장 | 저장 즉시 공개 — 분류·링크 오류를 걸러낼 수 없음 |
| AI가 짐작한 레포·사이트 그대로 사용 | 실측에서 엉뚱한 레포(`modelcontextprotocol/servers`)를 짐작 — 이름 일치·존재 확인 필수 |
