# 개발·학습 로그 2026-10

## 2026-10-11

- **유튜브 처리 방식 점검** — AI 개발 도구·게임 개발 도서관·칼럼의 유튜브 처리 비교. 공통 `parseYoutubeVideoId` + `youtube-nocookie` iframe, 추가 링크·마크다운 본문 자동 임베드. 원문 상단 임베드는 칼럼뿐이었음.
  - 게임 개발 도서관 상세에 `mediaKind=youtube` 원문 임베드 추가, iframe `loading="lazy"`.
- **「자막을 가져올 수 없어」 원인 규명** — 로컬은 InnerTube ANDROID로 자막 정상. Vercel에서만 실패 → 클라우드 IP 차단.
  - Python `youtube-transcript-api`를 Vercel 함수로 올려 실측: 4개 중 3개 `RequestBlocked`(같은 영상 로컬은 전부 성공). 라이브러리 교체로는 해결 불가 확인([learnings 0038](../learnings/0038-youtube-cloud-ip-block.md)).
  - 막힌 점: Python 함수 번들 373MB > 한도 → `excludeFiles`로 해결. 이 PC 터미널에서 `mylittlewebsite.p-e.kr` TLS 연결이 끊김 — **실제 배포 주소는 `my-little-website-client-self.vercel.app`** (ADR 0025·about.md의 도메인 기재와 다름, 정리 필요).
- **Gemini 영상 직접 분석 폴백** — 자막 fetch 실패 시 Gemini가 영상 URL을 보고 자막 대체 텍스트 생성 → 기존 섹션별 AI 정리 그대로. 로컬에서 youtube.com 차단 재현 후 칼럼 AI 채우기 47초 성공. `maxDuration` 60→300([decisions 0026](../decisions/0026-youtube-gemini-digest-fallback.md)). 점검용 `/ai-smoke-test`「Gemini YouTube 직접 분석」 추가.
- **유튜브 링크 일괄 등록 스크립트** — `server/scripts/bulk-youtube.ts`. 링크만 주면 중복 확인·섹션 분류·AI 채우기·레포 링크, AI 도구 영상은 도구 레포·사이트를 메인 링크로([decisions 0027](../decisions/0027-bulk-youtube-import-script.md)). 미리보기 단계만 실영상으로 테스트.
- **다음**
  - 미뤄둔 유튜브 링크 목록으로 `prepare` → 검토 → `save` (저장 단계 첫 실행).
  - 실제 레포 소개 영상(칼럼·게임 개발)으로 레포 추출 확인.
  - 확인 끝나면 `/ai-smoke-test` Gemini 테스트 입력칸·`POST /api/ai-smoke/gemini-youtube` 제거 검토.
  - 문서의 사이트 도메인(`mylittlewebsite.p-e.kr`) 기재 현행화.

## 2026-10-13

- **사이트 지식 MCP 서버** — 모은 자료를 AI 답변·자소서에 쓰기 위해 `POST /api/mcp`(Streamable HTTP, stateless, 인증 없음) 추가. 도구 5개(`list_scraps`·`get_scraps`·`get_source`·`get_portfolio`·`read_dev_notes`), 섹션은 AI 도구·칼럼·게임 개발·유용한 링크(172건)([decisions 0028](../decisions/0028-site-knowledge-mcp.md)).
  - 목록 전체(약 3.5만 자)를 LLM에 주고 고르게 함 — 검색 엔진·임베딩 생략. 처음엔 url·siteUrl까지 넣어 5만 자 → 고르기용 필드만 남겨 축소.
  - 원문: 유튜브 자막은 Vercel에서 막혀 `scrap_sources` 테이블 + 로컬 `backfill-sources`로 미리 저장. 캐시가 없으면 README·페이지는 실시간, 유튜브는 Gemini 요약(`ai-digest`).
  - 무인증 공개 엔드포인트라 `get_source`는 저장된 스크랩 링크만 허용(임의 URL 프록시 방지), `read_dev_notes`는 경로 우회 차단.
  - 프로젝트 목록을 `projects.json`으로 분리(server tsconfig `rootDir`가 client TS import를 막음).
- **MCP 연결 가이드** — `docs/mcp-guide.md` 하나를 원본으로 사이트 `/mcp`에서 렌더, 메인 머릿말에 진입점. 패치노트 페이지를 `MarkdownDocPage`로 일반화.
  - 막힌 점: `git mv` 뒤 `git add`에 옛 경로를 넣어 add 전체가 실패 → rename만 담긴 커밋이 push돼 잠시 빌드가 깨짐. 바로 후속 커밋으로 복구.
- **문서 현행화** — About 배포 절 Vercel 기준 재작성(AWS 절은 이전 기록), `p-e.kr` 미연결 명시. CHANGELOG 누락분(7월 CS 면접대비 섹션·서버리스 크래시 수정, 6월 게임 도서관 후속) 추가. ADR 상태 갱신(0018 대체됨, 0021·0024·0025·0027). api-spec에 게임 개발 도서관·메인 위젯·MCP 추가. docs/README 목차·루트 README 스택·포트·배포 정리.
- **다음** — [plans/2026-10-13-next-steps-plan.md](../plans/2026-10-13-next-steps-plan.md): `scrap_sources` SQL 실행·백필 → 크롬 확장 원클릭 저장 → 사이트 대화창.

## 2026-10-27

- **사이트 대화창 검색 오탐 수정** — 「루프 엔지니어링 알려줘」에 칼럼 대신 AI 개발 도구의 무관한 항목으로 답하던 문제. 로컬 재현 3/3 → 원인은 태그 완전 일치(모델이 띄어 써서 0건) + 모델의 섹션 짐작([error-fixes 0009](../error-fixes/0009-chat-search-misses.md)).
  - 태그 비교를 띄어쓰기·대소문자 무시·부분 일치로 고쳤지만, 섹션별 질문 11개 점검에서 3개 실패 → 근본 원인은 「필터로 좁게 짐작하고 그 결과를 전체로 믿음」. 대화창은 필터 없이 전체 목록(207건·약 2만 토큰)에서 고르게 바꾸고 10/10 통과.
  - 도구 한도 마지막 회차 빈 답변: `functionCallingConfig NONE`은 flash-lite가 무시, 도구 선언을 빼도 `functionCall`을 생성 → 지시문까지 붙여 해결.
  - 후속 질문: 모델이 이전 답변의 사이트 링크로 `get_scraps`를 부르게 siteUrl 입력 허용.
  - `read_dev_notes`에 `error-fixes/`·`journal/` 추가.
- **원문 조각 벡터 RAG 설계** — 지금 검색은 도구 호출형(agentic) RAG라 「어느 자료인지」는 잘 고르지만 요약에 없는 원문 속 내용은 못 찾음. 원문 실측(168건·약 260만 자, 40k 초과 12건)을 근거로 pgvector + `search_sources` 도구를 하이브리드로 추가하는 안([decisions 0033](../decisions/0033-source-chunk-rag.md), 제안). 구현 계획·SQL은 [plans](../plans/2026-10-27-source-rag.md).
- **다음** — ADR 0033 구현(SQL 실행 → 청킹·임베딩 모듈 → 백필 → 도구), `get_source`가 스크랩 id도 받게 할지 검토.
- **원문 조각 벡터 RAG 구현·측정** — 설계 당일 구현까지([decisions 0033](../decisions/0033-source-chunk-rag.md), [learnings 0039](../learnings/0039-agentic-vs-vector-rag-eval.md)).
  - 구현 전에 측정 도구(`eval-chat`)부터 만들어 기준선 확보 — 구현 후엔 "전" 수치를 다시 잴 수 없어서. 원문 속 질문은 DB에서 "원문엔 있고 제목·요약·태그엔 없는" 키워드를 찾아 문맥 확인 후 11개.
  - 사이트에서 직접 등록한 자료는 원문이 안 저장되던 빈틈 → 저장 경로별 훅 대신 Vercel cron 하나로(서비스 롤 키 + `CRON_SECRET`). 빠진 원문이 AI 도구 24건이었는데 원인은 빠른 저장이 영상 자막만 저장하고 영상에서 뽑은 레포 README는 안 저장하던 것.
  - 질문 유형 분기 대신 두 도구 병렬 호출 — 오전에 고친 섹션 짐작 오탐과 같은 실패를 피하려고.
  - 1차 측정에서 자료 찾기 회수율 94% → 83% 회귀: 조각이 들어오자 넓게 나열 → 깊게 설명으로 바뀜. 프롬프트로 89%. 원문 속 질문 33% → 79%(최종 after-v3 82%).
  - 막힌 점: `functionCallingConfig NONE` 무시(오전), Chrome 헤드리스 스크린샷 경로에 `\$` 이스케이프가 섞여 엉뚱한 파일명 → `cygpath -m`(슬래시 경로)로 해결. Framer url 수정은 권한 검사로 막혀 사용자에게 넘김.
  - 입력 토큰 +15% 원인 = 조각 8개. 목록의 사이트 전체 주소 반복(25%)을 경로로 줄여 +2.5%로, 정확도 그대로(after-v3).
  - 링크드인 포스트용 이미지 3장(작동 원리·결과·사례)과 초안.
