# 사이트 대화창이 있는 자료를 못 찾거나 「답변을 만들지 못했어요」

날짜: 2026-10-27

## 발생한 오류

1. **엉뚱한 섹션 답변** — 「루프 엔지니어링에 대해 알려줘」에 칼럼의 관련 글 2건(제목·태그에 「루프엔지니어링」)을 두고 AI 개발 도구의 무관한 항목을 엮어 답했다. 「칼럼에서 찾아」라고 해야 찾았다. 로컬 재현 3/3.
   - 같은 패턴 질문 11개 점검: 「무료 이미지 소스 사이트」(링크의 Pexels·Pixabay 놓침), 「목소리 클론 AI」(링크의 Uberduck·Supertone 놓침), 「AI로 2D 스프라이트」(게임 개발 3건 놓침) 실패, 「하네스 엔지니어링」 3건 중 1건, 「랙돌」은 찾고도 「직접 관련 자료는 없다」고 답함.
2. **도구 한도 도달 시 빈 답변** — 도구 호출 5회째에도 모델이 도구를 더 부르면 「답변을 만들지 못했어요.」 — 그때까지 모은 자료를 버림. 한도를 1회로 낮춰 재현.
3. **후속 질문에서 재검색** — 「두 번째 거 더 자세히」에 모델이 이전 답변의 사이트 링크 경로(`column/ai-1`)를 id로 넣어 `get_scraps`가 빈 결과 → `list_scraps`부터 다시 호출.

## 원인

1. `list_scraps` 태그 필터가 **완전 일치**였다. 모델은 `tag: "루프 엔지니어링"`(띄어쓰기)로 불렀고 태그는 `루프엔지니어링` → 0건. 이어서 모델이 섹션을 **짐작해** `section: "ai-tools"`만 다시 조회했다. 필터 결과를 전체라고 믿고, 같은 주제가 칼럼·유용한 링크·게임 개발에 흩어져 있다는 걸 모름. 태그 표기(`Ragdoll` vs 「랙돌」, `무료 에셋` vs 「이미지」)가 질문 단어와 다르면 같은 식으로 빠진다.
2. 마지막 회차도 도구를 열어 둔 채 호출했고, 응답에 텍스트가 없으면 고정 문구를 반환했다. `toolConfig.functionCallingConfig.mode: 'NONE'`은 gemini-3.1-flash-lite가 무시했고, 도구 선언을 빼도 대화 기록을 따라 `functionCall`을 또 생성했다.
3. 대화창은 다음 요청에 답변 텍스트만 다시 보낸다(도구 결과는 안 넘김). 모델이 볼 수 있는 건 답변 속 사이트 링크뿐인데 `get_scraps`는 `columns/ai-1` 형식 id만 받았다.

## 수정 방법

1. `list_scraps` 태그 비교를 대소문자·띄어쓰기 무시 + 부분 일치로(`knowledge/index.ts`). 대화창 시스템 프롬프트: **자료 질문은 `list_scraps`를 인자 없이 호출해 전체 목록에서 의미로 고르고, 섹션을 짐작해 좁히지 않는다**, 필터는 사용자가 섹션·태그를 지정했을 때만(`chat.ts`). 전체 목록은 207건·6만 자(약 2만 토큰) — flash-lite로 질문당 약 0.2센트.
2. 마지막 회차는 도구 선언을 빼고, 마지막 메시지에 「도구 호출 한도에 도달했다. 더 호출하지 말고 지금까지 확인한 결과만으로 답하라」 지시문을 붙인다.
3. `get_scraps`가 id 외에 siteUrl(전체 주소·`column/slug` 경로)도 받는다. 슬래시 없는 값(`links`)은 경로로 보지 않아 유용한 링크 전체에 걸리지 않는다.
4. `read_dev_notes` 허용 폴더에 `error-fixes/` 추가 — 이 문서 같은 버그 기록도 대화창·MCP가 읽는다.

## 결과/참고

- 같은 질문 10개 재점검: 전부 기대 자료 포함, 모두 `list_scraps` 1회(수정 전엔 짐작이 빗나가 2~3회). 섹션을 지정한 「칼럼 중에 MCP 관련 글」은 필터를 써서 DB와 같은 1건.
- 한도 1회 강제: 수정 전 실패 → 수정 후 3/3 정상 답변.
- 후속 질문(「두 번째 거 더 자세히」, 「모션 캡처 그거 더 자세히」): `get_scraps` 1회로 바로 답함(수정 전 +2회).
- 도구 결과 전체를 다음 요청으로 넘기는 방식은 안 함 — 목록만 2만 토큰이라 대화가 길어질수록 커짐. 링크로 이어받기가 되면 충분.
- 남은 점: 모델이 `get_source`에 `url` 대신 `id`를 넣는 경우가 있음(에러 후 재시도), 「본문까지 읽고」라고 해도 요약만으로 답하는 경우가 있음.
- 원문 속 세부 내용 검색은 별개 문제 — [ADR 0033](../decisions/0033-source-chunk-rag.md)(벡터 RAG, 제안). 그때도 이 수정의 「전체 목록에서 고르기」 규칙은 유지한다.
- 교훈: LLM에 필터 인자를 주면 **좁게 짐작하고 그 결과를 전체로 믿는다.** 목록이 감당할 크기면 필터 없이 다 주는 게 정확하다. 점검은 섹션별·표기가 다른 질문을 섞어서.
